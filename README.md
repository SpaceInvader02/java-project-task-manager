# Асинхронный сервис управления задачами

Это backend-приложение на Java. Оно позволяет создавать задачи через REST API, складывает их в очередь и обрабатывает в фоне.

Идея простая: пользователь отправляет запрос на создание задачи, сервис быстро отвечает, а сама работа выполняется отдельно worker-потоками. Поэтому HTTP-запрос не висит, пока задача выполняется.

## Что умеет сервис

- создавать задачи;
- хранить список задач;
- показывать задачу по `id`;
- показывать только статус задачи;
- отменять задачу;
- фильтровать задачи по статусу и приоритету;
- отдавать список задач страницами;
- обрабатывать задачи асинхронно;
- учитывать приоритеты задач;
- запускаться локально или через Docker.

## Как устроена задача

У каждой задачи есть:

- `id` - уникальный идентификатор;
- `title` - название;
- `description` - описание;
- `priority` - приоритет;
- `status` - текущий статус;
- `createdAt` - время создания;
- `startedAt` - время начала обработки;
- `completedAt` - время завершения;
- `result` - результат выполнения;
- `error` - текст ошибки, если задача завершилась с ошибкой.

Приоритеты:

```text
LOW
MEDIUM
HIGH
```

Статусы:

```text
NEW
PENDING
IN_PROGRESS
COMPLETED
FAILED
CANCELLED
```

Обычный жизненный цикл задачи:

```text
NEW -> PENDING -> IN_PROGRESS -> COMPLETED
```

Если произошла ошибка:

```text
NEW -> PENDING -> IN_PROGRESS -> FAILED
```

Если задачу отменили:

```text
PENDING -> CANCELLED
IN_PROGRESS -> CANCELLED
```

## Как работает асинхронность

Когда приходит запрос:

```http
POST /api/v1/tasks
```

сервис создает задачу, сохраняет ее и кладет в очередь. После этого пользователь сразу получает ответ.

Сама задача выполняется не в HTTP-запросе, а в фоне. Для этого используются worker-потоки.

Worker-поток - это отдельный поток, который ждет задачи в очереди. Когда задача появляется, worker забирает ее и выполняет.

Количество worker-потоков настраивается через переменную:

```text
TASK_WORKERS
```

Например, если `TASK_WORKERS=4`, сервис может обрабатывать до четырех задач одновременно.

Очередь задач приоритетная. Это значит, что задачи с `HIGH` будут взяты в работу раньше, чем `MEDIUM` и `LOW`. Если приоритет одинаковый, раньше выполняется задача, созданная раньше.

## Как хранятся задачи

Сейчас задачи хранятся в памяти приложения. Это называется in-memory storage.

В коде за хранение отвечает интерфейс `TaskRepository`, а текущая реализация называется `InMemoryTaskRepository`.

Плюсы такого подхода:

- не нужна база данных;
- проще запустить проект;
- удобно для учебного задания;
- хорошо видно бизнес-логику.

Минусы:

- после остановки приложения задачи пропадают;
- если запустить несколько копий сервиса, у каждой будет свой список задач.

Для production-версии вместо `InMemoryTaskRepository` можно добавить реализацию через PostgreSQL или другую базу данных.

## Структура проекта

```text
src/main/java/org/example/vvpd
```

Основные пакеты:

- `controller` - REST API;
- `service` - бизнес-логика и асинхронная обработка;
- `repository` - хранение задач;
- `model` - задача, статусы, приоритеты;
- `dto` - объекты запросов и ответов;
- `exception` - ошибки приложения;
- `common` - общий обработчик ошибок.

Главные файлы:

- `TaskController` - принимает HTTP-запросы;
- `TaskService` - создает задачи, кладет их в очередь и управляет worker-потоками;
- `Task` - модель задачи и переходы между статусами;
- `TaskRepository` - контракт для хранения задач;
- `InMemoryTaskRepository` - хранение задач в памяти.

## Как проверить через Swagger

1. Запустить приложение.
2. Открыть `http://localhost:8080/swagger-ui/index.html`.
3. Открыть блок `task-controller`.
4. Выбрать `POST /api/v1/tasks`.
5. Нажать `Try it out`.
6. Вставить JSON:

```json
{
  "title": "Test task",
  "description": "My first async task",
  "priority": "HIGH"
}
```

7. Нажать `Execute`.
8. Скопировать `id` из ответа.
9. Проверить задачу через `GET /api/v1/tasks/{taskId}`.
10. Проверить статус через `GET /api/v1/tasks/{taskId}/status`.

Через несколько секунд статус должен стать:

```text
COMPLETED
```

## API

Создание задачи:

```http
POST /api/v1/tasks
Content-Type: application/json

{
  "title": "Build report",
  "description": "Prepare async report",
  "priority": "HIGH"
}
```

Получение списка задач:

```http
GET /api/v1/tasks
```

С фильтрами:

```http
GET /api/v1/tasks?status=COMPLETED&priority=HIGH&page=0&size=20
```

Получение задачи по id:

```http
GET /api/v1/tasks/{task_id}
```

Получение статуса задачи:

```http
GET /api/v1/tasks/{task_id}/status
```

Отмена задачи:

```http
DELETE /api/v1/tasks/{task_id}
```

## Пагинация

Пагинация нужна, чтобы не отдавать огромный список задач целиком.

Пример:

```http
GET /api/v1/tasks?page=0&size=20
```

Это значит: вернуть первую страницу, максимум 20 задач.

В ответе есть:

- `items` - задачи на текущей странице;
- `page` - номер страницы;
- `size` - размер страницы;
- `total` - сколько всего задач найдено;
- `totalPages` - сколько всего страниц.

## Обработка ошибок

Сервис обрабатывает типичные ошибки:

- задача не найдена;
- неверный UUID;
- пустое название;
- пустое описание;
- отсутствует приоритет;
- неверный статус или приоритет;
- ошибка во время выполнения задачи.

Ошибки возвращаются в JSON-формате, чтобы клиент мог нормально их обработать.

## Docker

Docker нужен, чтобы приложение можно было запустить в одинаковом окружении на разных компьютерах.

В проекте есть:

- `Dockerfile` - инструкция, как собрать и запустить приложение в контейнере;
- `docker-compose.yml` - удобный запуск сервиса одной командой.

Запуск:

```powershell
docker compose up --build
```

После запуска Swagger будет доступен здесь:

```text
http://localhost:8080/swagger-ui/index.html
```

Остановить:

```powershell
docker compose down
```

Если команда `docker` не работает, значит Docker Desktop не установлен или не запущен. В таком случае проект можно запускать обычным способом через Gradle.
